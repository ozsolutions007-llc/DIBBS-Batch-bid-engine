1 · Profile (once). Click ✎ PROFILE, enter your Quoter CAGE and company defaults (FOB origin city/state, payment terms), then 💾 SAVE PROFILE. Every batch row inherits these. Your CAGE must match the account you log into DIBBS with — a mismatched CAGE fails the whole file with error (006)-(007).
2 · Link your output folder (once). Click 🔗 LINK OUTPUT FOLDER and pick where batch files should land. They're written as plain .txt — exactly what the DIBBS upload dialog wants. No folder linked = zip download instead.
3 · Drop solicitations. Drag PDFs onto the drop zone — one, fifty, or a whole folder that also contains your pricing Excel (columns: Sol#, Part Number, Trace Cage code, BID PRICE). The engine reads everything the RFQ states: set-asides, Buy American, multi-CLIN lines, AIDC quantities, quality certs, standard vs approved-source items. QPL items are auto-blocked (they can't be batched correctly).
4 · Review the greens. Each solicitation is a row; a green ● READY light means every DIBBS rule passes. Amber rows say exactly what's missing — usually just a price or the manufacturer. Open a row's LINE DETAILS to edit anything the PDF read.
5 · Batch Ready. One click stages every green row and writes the BB_*.txt files to your folder. Upload them at dibbs.bsm.dla.mil → RFQs → Quote → Upload. If DIBBS ever rejects a line, paste the validation text into the Rejection Fixer at the bottom.

Field Guide — batching DIBBS without BQ files
Every rule below was proven against live DIBBS validation — each one started as a real rejected upload. The engine applies all of this automatically on every PDF drop; this page is the "why", for when a batch bounces and you need to know what DIBBS is actually checking.
The core idea

Some tools avoid these errors by downloading DLA's pre-formatted BQ batch files and copying DLA's own values for the "must match RFQ" fields. That works, but it chains you to a daily BQ download. Everything DIBBS validates is also stated in the solicitation PDF itself — the set-aside clause, the FOB terms, the item type, the quality requirement. This app reads those facts straight off the document, so the PDF you were going to read anyway is the only input you need.

(006)-(007) — Invalid Quoter CAGE combination

Field 6 must be a CAGE your DIBBS login is registered for. This fails the whole file before any other rule is checked — if every line failed with this, it's your profile, not your rows. A real 8-row batch died this way under a test profile. The app warns when the active profile CAGE has never exported on your machine.

(003) — Invalid Small Business Set Aside Indicator

Field 3 must match whether the RFQ is a set-aside — and the SF18 cover checkbox is a graphic you can't read from text. The reliable signal is the FAR 52.219 notice clause number in the body: 52.219-6 → Y (Total Small Business), 52.219-3 → H (HUBZone), 52.219-27 → R (SDVOSB), 52.219-29 → E (EDWOSB), 52.219-30 → L (WOSB), 52.219-18 → A (8(a)). No notice clause → N (unrestricted). Two traps: every RFQ's reps boilerplate mentions set-asides by name — only the clause numbers count; and 52.219-31 "Small Business Reserve" is not a set-aside (a real upload passed N with it present).

(068) — Invalid Buy American Indicator

Field 68 is not about the RFQ's clause list — every solicitation prints Buy American boilerplate. It tracks the set-aside status: unrestricted RFQ + domestic end product → N; set-aside RFQ → Y (set-asides require domestic end products). Proven both directions: Y on unrestricted RFQs rejected twice, N on set-asides rejected twice, and the opposites passed. Field 70 stays D (domestic) either way for a normal reseller quote.

(002) — Invalid Solicitation Type

Derived from the solicitation number: -T- → F (fast auto), -U-/-D- → I (AIDC), -Q- → leave blank. One refinement from a real rejection: a set-aside T-type runs as P (auto evaluation), not F — fast-auto apparently excludes set-asides.

(032) / wrong FOB or Inspection Point

Read them from the schedule section ("DELIVER FOB: ORIGIN", "INSPECTION POINT: DESTINATION") — never from block 7 of the cover page, which preprints "FOB DESTINATION (See Schedule)" on every SF18 regardless of the real terms. If you quote a different FOB/Inspection than the RFQ states, BID_TYPE must change to BW/AB; matching the RFQ keeps BI.

(046) / wrong PR number

Block 3 of the cover page is labelled "REQUISITION/PURCHASE REQUEST NO." — one box, two different numbers. An alphanumeric value there (e.g. W25G1V6210001O) is the customer's MILSTRIP requisition, not the PR. The real PR is the 8-10 digit number in the schedule's PR column (or the GOVT USE table a few pages in). A requisition submitted as the PR gets rejected.

(105)-(110) — Item type: approved-source vs standard vs QPL

The item description section tells you which of three games you're playing:

Approved-source item (105 = P). The RFQ lists who may supply it as "CAGE P/N part" lines (e.g. "65836 P/N RBC69-1U"). Quote 106=1 (exact product), 107/108 = an approved CAGE + P/N exactly as listed, 103 = that CAGE. Field 110 stays blank.

Standard / milspec item (105 = D). No approved-source list at all — the item is governed by the cited standard (NAS, AN, MS, MIL). Fields 106/107/108 must be BLANK, field 110 = 1 (supplies IAW all specs cited), and the manufacturer goes in field 104 by name ("CBS FASTENERS") — no CAGE needed or expected. Quoting one of these with a part number draws (105)(106)(107)(108)(110) all at once.

QPL item (105 = Q) — don't batch it. QPL means the manufacturer must be on DLA's tested-and-qualified list, and fields 112/113 demand the qualifying source's CAGE, which nothing hands you. There is no way to complete the row correctly; this app blocks it at staging. Pursue QPL items manually on DIBBS if they're worth it.

(117)-(119) — Higher-Level Quality

Field 117 must match the RFQ. The trigger is the explicit sentence "the manufacturer's inspection system at a minimum must comply with SAE AS9003 or ISO 9001 tailored…" → 117 = 6, 118 = 6 (or 7/8 if the mfr holds full ISO 9001/AS9100). The RQ001 marker alone is not the trigger — a real upload passed 117=N with RQ001 present but no prose, and another was rejected 117=N with the prose present. 119 stays blank unless 118 = 2 (Other Equivalent).

"Incomplete Quote — Missing Solicitation Lines"

A multi-CLIN RFQ must have every line quoted: one 121-field row per CLIN, header fields (1-43, 121) identical on every row, fields 44 / 46-51 varying per line. Each CLIN section in the PDF carries its own PR#, quantity, delivery and FOB lines — read per section, not once. Submitting 1 of 7 lines fails the solicitation.

Format gotchas that fail silently

121 fields, every one double-quoted, comma-delimited, CRLF line endings. No dashes in SOL#, NSN, or CAGE (the PDF prints them dashed; DIBBS wants them stripped). Dates MM/DD/YYYY. CAGEs exactly 5 characters — a part number in field 107 kills the whole file on length. Field 103 OR 104 identifies the manufacturer (they're alternatives, not both). Reserved columns stay empty.

All of the above runs automatically on every PDF drop — set-aside, Buy American, item type, quality, CLINs, PR#, FOB. If DIBBS still rejects a line, paste the validation text into the Rejection Fixer on the Batch Engine tab, and send the validation page to whoever maintains this app: every rule here exists because a rejection taught it.
